# Проверка Snipcast 0.35.0 — 7 октября 2026

## Сборки и изоляция

Проверены debug Windows/WebView2 с Vite и оптимизированный exe со встроенным frontend.
Нативные экземпляры используют отдельный идентификатор `com.snipcast.selection-qa`,
`SNIPCAST_DATA_DIR`, отключённые глобальные хоткеи и HTTP API, отдельные CDP-порты.
При заданном профиле временные снимки и очистка старых файлов также изолированы в `capture-cache`.
Обычный процесс пользователя не останавливался. Официальный exe собирается с `com.snipcast.app`.

## Выполнено

- `npm run build`, `cargo test`: 16 Rust-тестов прошли; существующий интеграционный тест PaddleOCR остаётся помеченным ignored.
- `capture_035.py`: пересечение двух виртуальных мониторов, отрицательный origin, DPI 100/150/200% и разный scale в метаданных мониторов, точные размеры и цвета PNG, размещение тулбара на экране отпускания.
- Быстрый выбор 1–5; Shift по горизонтали/вертикали, продолжение штриха после Shift, перемещение/удаление, один шаг undo/redo. Русский `key=с` с физическим `code=KeyC` проверен синтетическим событием в браузере.
- Обычный ввод цифр, Enter и стрелок в textarea; Ctrl+C не запускает экспорт при вводе текста. Enter вне поля: отмена диалога сохраняет захват, успешная запись закрывает его.
- Суммы: минус, запятая/точка, NBSP между разрядами, числа больше диапазона Number, нет чисел, неоднозначная запись, ошибка OCR и сохранение буфера.
- `capture_text.py`: 18 групп регрессий текста, геометрии, WYSIWYG PNG, отмены, IME и истории. `capture_opening.py`: 7 регрессий открытия/повторного открытия. `capture_assist.py`: обе темы и DPI 100/150/200%, автодействие пресета одним кликом.
- `pin_annotation.py`: обе темы и DPI 100/150/200%, копирование, применение, отмена, повторное открытие и ошибка сохранения.
- Нативный захват: один overlay, фактическая геометрия рабочего стола, системный курсор на один пиксель, Ctrl+C закрывает окно; Windows clipboard PNG сверяется по размерам и пикселям исходного кадра.
- Нативный OCR: числа на настоящем закрепе захвачены с рабочего стола; системный OCR дал сумму `10,3`, Windows текстовый буфер проверен, захват остался открытым. Нативная запись PNG в файл проверена по пикселям.
- Нативные закрепы: контекстное меню, Windows clipboard, исходное разрешение после аннотирования, выбранный новый закреп и переключение между двумя, снятие выбора снаружи, позиция изображения при входе в редактор, восстановление геометрии после применения/отмены. У screenshot alpha в пустой части редактора равна 0; GetWindowRgn возвращает объединение, PtInRegion исключает пустой угол.
- Нативные обновления: тёмная/светлая темы, прокрутка заметок; изменение релиза между показом и установкой обновляет предложение; пропуск сохраняется, ручная проверка видит пропущенную версию; новая версия предлагается; закрытие подавляет показ до следующего дня; один запрос за день при перезапуске; сетевой 503 записан в журнал без окна; во время захвата уведомление скрыто и возвращается после закрытия.
- Пропущенные дни и старт после 10:00 эмулировались состоянием отдельного профиля. Время компьютера не менялось, реальное пробуждение ОС не проверялось.

## Производительность

Контролируемый браузерный сценарий: 120 движений ручного выделения с лупой,
один источник 1920×1080 или 3840×1080, интервал requestAnimationFrame.
Это интервал кадра, а не полное измерение физического движения мыши до свечения экрана.
Ограничение CPU через CDP в 6 раз — эмуляция, не реальный слабый компьютер.
JS heap не включает память canvas, GPU и нативного процесса.

| Виртуальные экраны | CPU | До: медиана / p95, мс | После: медиана / p95, мс | JS heap, МБ |
| --- | --- | --- | --- | --- |
| 1 | 1× | 16.8 / 18.1 | 16.6 / 18.1 | 10.6 → 10.0 |
| 1 | 6× | 45.1 / 69.8 | 28.0 / 34.2 | 11.9 → 10.6 |
| 2 | 1× | 16.9 / 26.7 | 16.9 / 29.3 | 10.0 → 10.0 |
| 2 | 6× | 55.8 / 64.3 | 34.4 / 43.9 | 11.2 → 11.2 |

Старый debug backend с **текущим** frontend: открытия [1884.8, 1861.4, 1857.2, 1843.4] мс.
Новый debug backend: [594.7, 587.5, 559.1, 589.3] мс. Это сравнение backend, не двух полностью идентичных релизных окружений.
Оптимизированный exe 0.35.0 со встроенным frontend: [449.7, 257.3, 256.8, 259.8] мс — первый запуск и три повторных.
Момент готовности проверялся по фактически показанному overlay после декодирования и барьера отрисовки.

Память дерева процессов (app и WebView2/CDP) измерялась при четырёх открытиях:
старый debug: private 439, 514, 548, 547 МиБ;
новый release: private 343, 508, 554, 578 МиБ.
Суммарный working set release: 563, 688, 706, 713 МиБ.
Условия debug/release различаются; уменьшение общей памяти этими результатами не доказано.
В реализации устранены повторные canvas allocations при движении, перерисовка завершённых фигур при новом штрихе и сортировка кандидатов на каждом движении.

## Границы проверки

На машине доступен один реальный монитор 1920×1080 при 100% DPI.
Нативное пересечение двух физических экранов, смешанный DPI и отрицательные координаты не подтверждены на реальном оборудовании.
Они покрыты браузерной геометрией/PNG и Rust-тестом чёрных промежутков между мониторами.
Реальный слабый ПК, переключение раскладок средствами Windows, настоящий сон/пробуждение,
ручная работа с системным диалогом «Сохранить как» и установка обновления с перезапуском не выполнялись.
Выбор движка OCR переиспользует существующую команду; нативно в этой проверке использован системный OCR.
