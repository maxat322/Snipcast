# Snipcast 0.36.0 — запись и отдельный редактор видео

> Позднее выявлены повреждённые MP4/GIF для областей с шириной, не кратной 16.
> Проверка 640 × 400 ниже не охватывала этот случай. Исправление и расширенная
> нативная проверка описаны в [отчёте 0.36.1](qa-0.36.1-video.md).

Реализован выбранный вариант с отдельным окном редактора в текущем стиле
Snipcast. После остановки записи появляются предпросмотр, миниатюры, границы
фрагмента, обрезка кадра и экспорт MP4/GIF. Поддерживаются тёмная и светлая темы.

## Как пользоваться

1. Трей → «Записать видео области», значок камеры справа от поиска в палитре
   или «Видео» на панели обычного выделения скриншота.
2. Выделить область внутри одного монитора. В специальном режиме выбрать
   15/30 кадров/с и необязательный звук системы. Нажать «Записать» или Enter.
3. Плавающая панель показывает длительность и размер; доступны пауза и остановка.
   Панель исключается из Windows Graphics Capture даже при перемещении внутрь области.
4. В отдельном редакторе выбрать начало/конец численно или маркерами на шкале.
   «Обрезать кадр» включает рамку с перемещением и изменением размера.
5. Сохранить MP4 с выбранным качеством либо GIF с шириной до 960 и 10/15 кадров/с.
   Диалог подтверждает замену существующего файла. Отмена экспорта сохраняет
   старый файл; редактор остаётся доступен.

## Движок, размер и память

- Статически встроены заголовки [wcap](https://github.com/mmozeiko/wcap),
  закреплённые на `aa25ccb806d7a6e1c0bfdcca863aabcd8e9badfa`, лицензия Unlicense.
  Единственная правка upstream: возврат HRESULT финализации MP4 для показа ошибки.
- Захват: WGC/D3D11; MP4: системный Media Foundation H.264/AAC; GIF: системный WIC.
  Дополнительные FFmpeg/кодеки/DLL для видео не распространяются.
  `cc` — зависимость только этапа сборки. Заголовки и шейдеры vendor занимают около 140 КБ.
- По умолчанию выбран компактный MP4. Битрейт зависит от разрешения/частоты;
  итоговый размер зависит от содержимого. Расчёт в интерфейсе приблизительный.
  Экспорт MP4 перекодирует выбранный фрагмент, что позволяет обрезать между ключевыми кадрами.
- Кадры остаются в нативном движке: запись не передаёт полноразмерные кадры в JS.
  Проигрывание читает MP4 порциями до 2 МиБ, миниатюр восемь, экспорт декодирует
  последовательно. Окно выделения с полноэкранным canvas освобождается при начале записи.
  Временная исходная запись удаляется при закрытии редактора; остатки после сбоя — при запуске.
- GIF ограничен по ширине/частоте, использует адаптивную палитру, объединяет
  одинаковые кадры и зацикливается. Для большого движущегося изображения GIF
  может быть значительно больше MP4. Звук в GIF отсутствует.

## Проверки

`tests/video_native.py release` запускал отдельный Tauri identifier
`com.snipcast.video-qa` с изолированным `SNIPCAST_DATA_DIR`, встроенным production
frontend и WebView2/CDP. Пользовательское приложение и его настройки не менялись.

Проверены настоящие WGC-записи со звуком и без него, 15/30 кадров/с,
Enter/Escape, пауза без увеличения длительности, отдельные окна, проигрывание,
восемь декодированных миниатюр, границы фрагмента, рамка кадра, смена темы,
MP4/GIF, оба вида отмены, сохранность существующего файла, очистка временного
MP4 и повторное выделение после освобождения окна захвата.

Экспортированный MP4 декодирован в WebView2: проверены размер, длительность,
цвета сверху/снизу (обрезка и ориентация) и отсутствие панели управления в кадре.
Аудио MP4 отдельно декодировано в AudioContext: два канала и ожидаемая длительность.
GIF прочитан Pillow: разрешение, кадры, суммарная задержка и `loop=0`.
Ошибок JavaScript нет, журнал нативного процесса пуст.

| Результат release QA | Значение |
|---|---:|
| Исходная запись с движущимся маркером и звуком | 640 × 400, 3,479 с, 54 732 байта |
| MP4 после обрезки времени и кадра | 480 × 300, 2,039 с, 31 946 байт |
| GIF того же фрагмента | 480 × 300, 2 с, 17 кадров, 34 983 байта |
| Запись интерфейса без звука | 640 × 400, 1,543 с, 20 727 байт |
| Rust-тесты | 19 прошли |
| Регрессия текстовых аннотаций, DPR 1/1,25/1,5/2 | 18 групп прошли |

На QA-машине использовался программный кодировщик Windows: аппаратный H.264
недоступен. Поэтому аппаратная ветка не проверена, фактическая частота ниже
выбранного предела (метаданные тестовых файлов: 21 и 12 кадров/с).
Нативный тест выполнен на одном мониторе с DPI 100%; другие DPI, физические
конфигурации мониторов и Windows без компонентов мультимедиа не проверены.

Измерен working set release-процесса: 32 083 968 байт до захвата,
151 379 968 при записи со звуком, 56 250 368 в редакторе. Сумма working set
процесса и дочерних WebView2: 442 372 096 / 668 860 416 / 582 422 528 байт.
Эта сумма повторно учитывает общие страницы и не равна уникально занятой RAM;
замер включает тестовое окно настроек. Длительная запись и аппаратный кодировщик
по памяти не измерялись. Основной существующий расход интерфейса — WebView2.
