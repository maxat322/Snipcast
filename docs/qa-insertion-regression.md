# Быстрая палитра: блокировка вставки после удаления

16 октября 2026. Предыдущая локальная сборка 0.36.11 с SHA-256
`1efe55261e944d78491f678aea13bc3d509e357c466b7e071238609032d941ef`
добавила регрессию. При ручном повторе пользователя прочитан статус
работающего приложения: «Удаление команды не подтверждено — шаблон не
вставлен». Сбой подтверждён именно на этапе проверки после удаления;
конкретное приложение и особенности его UIA-провайдера не установлены.

Промежуточный вариант `14f6cb9e…` пытался подтверждать UIA-выделение и читать
документ после удаления. При повторе пользователь сообщил: «Команда осталась,
шаблона нет»; статус — «Выделение команды не подтверждено — вставка отменена».
Этот вариант также отклонён. Из пользовательских проверок установлены два
ложных отказа UIA, но конкретное поведение стороннего провайдера не доказано.

Итоговый механизм сохраняет проверку полного слова, целевого поля и ревизии
ввода. EDIT и Scintilla выделяют точный диапазон через собственные сообщения,
проверяют границы выделения, выполняют Clear, затем сверяют положение,
длину и сохранённый префикс; вставка выполняется сообщением Paste.

Остальные редакторы выделяют команду настоящими Shift+Left, а не UIA Select.
Копирование должно вернуть свежий точный фрагмент; дополнительно проверяется
символ перед ним, чтобы не оставить неотслеженное начало слова. Перед Cut
выделение повторно проверяется копированием. Только свежий точный результат
Cut разрешает записать шаблон в буфер и отправить Ctrl+V. Устаревшие UIA-каретка
или выделение после успешного Cut больше не блокируют вставку. Ожидание
буфера сначала проверяет номер последовательности, чтобы не открывать его
одновременно с обработчиком Copy/Cut. Первый результат из пустого буфера
также принимается, если номер изменился с нуля на ненулевой.

После отправки удаления другой способ автоматически не пробуется.
Проверка смены окна, поля или пользовательского ввода продолжает отменять
вставку. Шаблоны с формами и вложениями используют тот же механизм.

Проверки выбраны через `test:changed --list --focus text-suggestions --files
src-tauri/src/suggestions_windows.rs`, затем запущена та же команда без
`--list`. Прошли 16 тестов, в том числе прежние отрицательные сценарии.
Новый дочерний тест создаёт отдельные неназванную Windows window station,
рабочий стол и буфер обмена. Выполнены 60 настоящих WM_CLEAR / записи буфера /
WM_PASTE с кириллицей, многострочным текстом и Unicode; проверено точное
сохранение окружающего текста и отказ при снятом выделении. SwitchDesktop,
SendInput и буфер пользователя в этом тесте не используются.

Новый тест подтверждает нативный путь EDIT, а не все сторонние приложения.
Для редакторов без нативного адаптера подтверждением служит свежий результат
стандартной операции Cut; независимого чтения удалённого диапазона нет.
Редактор, переопределяющий Cut или ограничивающий Copy, требует отдельной
проверки. Терминалы остаются неподтверждёнными. Прежние тесты с подменой
транспорта не считаются подтверждением совместимости сторонних приложений.
Исходный отказ получен из пользовательского приложения через диагностический
CDP-сеанс без перевода фокуса. Текст ввода и содержимое шаблонов не записывались.

В итоговой сборке `1d9653d3…` пользователь повторил вставку в том же поле и
подтвердил: **«Шаблон вставился, команда удалена»**. Статус работающего
приложения после попытки пустой, ошибок нет. Это подтверждает устранение
воспроизведённой регрессии; отдельная проверка всех приложений не проводилась.

Обе копии EXE (`dist-release/snipcast.exe` и `C:\sz\snipcast.exe`) обновлены
и сверены по SHA-256. Временное диагностическое подключение отключено штатным
перезапуском. В `dist-release` оставлены только актуальный EXE и контрольная
сумма. Выполнен `cargo clean` изолированного target, удалены `.qa-work` этой
задачи, `dist` и локальные кэши Vite; освобождено около 2,16 ГиБ.
