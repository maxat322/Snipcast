# Быстрая палитра: центр экрана, форма и подтверждение

14 октября 2026. Исправления по снимку и обратной связи пользователя о MAX.

## Изменения

- Если каретка недоступна, быстрая палитра показывается в центре рабочей области
  монитора исходного окна. Прямоугольник всего окна MAX больше не используется
  как якорь текстового поля. Координаты результата сохраняются во время набора.
- Форма получает высоту по фактическому содержимому и использует всю доступную
  высоту монитора. Если места снизу мало, форма поднимается; без каретки она
  центрируется. Полосы прокрутки нет. Большое число полей распределяется по
  страницам; введённые значения сохраняются при переходах.
- Открытие формы сначала активирует её нативное окно. Значения и фокус поля
  инициализируются перед отрисовкой. Подтверждение срабатывает на отпускании
  первого Enter; удержание/повторы не создают дополнительные вставки. IME-Enter
  не подтверждает форму. Последнее значение читается из самого input, даже
  если очередной React-render ещё не завершился.
- Enter при видимой плашке принимается даже до окончания подтверждения
  отрисовки последнего запроса. Поиск завершается по актуальному буферу,
  прежде чем выбирается шаблон. Смена контекста отменяет такой запрос.
- После формы восстанавливаются окно и дочернее поле. UIA даётся ограниченное
  время на обновление фокуса до начала изменения текста. Собственные переходы
  фокуса не считаются изменением команды; внешний ввод проверяется по счётчику
  событий за всё время заполнения формы.
- Для поля без читаемого диапазона серия Backspace заменена на Shift+Left,
  затем Ctrl+C и проверку точного свежего выделения. Только совпадение целого
  фрагмента разрешает Ctrl+V. Дополнительно проверяется один символ слева:
  буква, цифра, подчёркивание или продолжение триггера означают, что отслежен
  только хвост команды. Такая замена запрещена. Разделитель исключается из
  выделения и исходный фрагмент проверяется ещё раз. При несовпадении текст не удаляется, выделение
  сворачивается обратно, если пользователь не изменил контекст. Клавиши
  маркируются как собственные. После частичной вставки повтор сессии запрещён.
- Потерянный или слишком длинный буфер слова больше не возобновляется с хвоста.
  В MAX после стороннего исправления без доступного текста ожидается новое слово.

Свежесть проверки clipboard определяется по
[GetClipboardSequenceNumber](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber).
Вставка использует существующий буфер обмена; копируемый фрагмент не журналируется.

## Проверки

Выбор выполнен через `test:changed --list --focus text-suggestions --files ...`
только по файлам этой задачи, затем запущен тот же выбор без `--list`.

| Проверка | Результат |
|---|---|
| Rust: 7 тестов поиска, буфера, настроек и переменных | Пройдено |
| Rust: 10 тестов Windows-логики, центра, размеров формы, свежести выделения, Enter и маркировки | Пройдено |
| Скрытый HWND: выделение кириллицы и скругления, без смены foreground | Пройдено |
| Headless UI: первый Enter, удержание, IME, последний символ, страницы без прокрутки, ошибки/отмена, вложения, обе темы | Пройдено |
| Живая вставка нового механизма Ctrl+C в MAX | Не проверялась в этом прогоне |

Проверки с захватом рабочего стола пользователя не запускались. Модульные
проверки свежести clipboard не заменяют полный прогон поведения Qt/QML в MAX;
он требует отдельного интерактивного Windows-окружения.

Компактные подтверждения: [qa-artifacts/quick-palette-fixes](qa-artifacts/quick-palette-fixes/).

## Что нового

При недоступной каретке — центр экрана. Форма без прокрутки, подтверждение
одним Enter на отпускании клавиши. В непрозрачных полях заменяется проверенное
выделение команды вместо удаления цепочкой Backspace.

## Сборка и очистка

Производственная сборка без `inline-qa` установлена в `dist-release/snipcast.exe`
и запущена после очистки. Версия разработки — 0.36.11, SHA-256:
см. `build.json` в каталоге подтверждений.
Путь и версия текущего процесса проверяются в `running-release.json`.

Предыдущий экземпляр завершён обычным `WM_QUIT` после проверки, что его рабочие
окна скрыты и нет окон записи/редактора/закрепов. Пользовательские данные сохранены.
`cargo clean` удалил 9 308 файлов, 3.5 GiB, только из изолированного target этой
задачи. После дополнительной проверки левой границы второй `cargo clean`
удалил ещё 4 827 файлов, 2.1 GiB. В сумме освобождено около 5.6 GiB.
Временные результаты, локальный кэш Vite и собственный Vite-сервер очищены;
компактные доказательства перенесены в `docs/qa-artifacts/quick-palette-fixes`.
