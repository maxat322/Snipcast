# Тип выбранной фигуры и язык текста

22 октября 2026. Локальная доработка 0.36.13, без публикации выпуска.

В панели «Фигура» смена прямоугольника, квадрата, круга или овала преобразует выбранный объект и задаёт тип для следующего рисования. Сохраняются идентификатор и оформление объекта, поддерживаются отмена и повтор. Кнопка активного типа отражает выбранную фигуру, в том числе при повторном выборе с выключенным инструментом. При преобразовании вытянутого объекта в круг или квадрат сохраняется центр, а стороны выравниваются по большему размеру.

Нативно воспроизведена проблема языка: после штатного запроса Windows на переключение раскладки поле WebView2 имело русскую HKL, а поток окна Tauri оставался с английской HKL. При перехвате текстовой клавиши получалось `qq` вместо `qй`. Исправление в режиме ввода текста получает поток поля с клавиатурным фокусом через GetGUIThreadInfo, проверяет принадлежность окна и читает его текущую раскладку. Обработка остальных команд захвата сохранена. Исключений для Alt+Shift, Ctrl+Shift или Win+Space не добавлено.

Основание для выбора API: [GetKeyboardLayout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeyboardlayout) возвращает язык указанного потока; [GetGUIThreadInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguithreadinfo) позволяет определить окно с фокусом.

Временная деактивация окна больше не фиксирует текст автоматически. Сессия и каретка сохраняются при показе системных окон выбора языка; клик вне текста, Ctrl+Enter и экспорт по-прежнему завершают редактирование.

Проверки выбирались через `test:changed -- --list --files`, затем запускался тот же список без `--list`. Браузерно проверены преобразование выбранного объекта, сохранение оформления, undo/redo, повторный выбор объекта, центр и равные стороны, сохранение сессии после blur/focus и завершение по клику вне текста. Выполнены регрессии захвата и редактора закрепа в обеих темах и при DPI 1 / 1.5 / 2.

Нативный тест использует отдельный идентификатор `com.snipcast.qa-input-language`, собственный каталог данных и реальные SendInput-события. Переключение EN → RU → EN проверяется штатным WM_INPUTLANGCHANGEREQUEST у поля WebView2; глобальные языковые настройки не меняются, исходная раскладка восстанавливается. Реальный системный интерфейс выбора языка и конкретное пользовательское сочетание отдельно не автоматизировались. Дополнительно проверяется сохранение текста при смене активного окна и продолжение ввода после возврата.

В целевой нативной пробе режим текстового ввода устанавливается командой `snipcast_capture_keyboard_state` после фокусировки textarea. Это проверяет обработку раскладки нативным перехватчиком и сохранность сессии; полная доставка всех системных сочетаний этой пробой не подтверждается.

Пройдены три браузерных набора, три Rust-теста правил клавиш и целевая нативная проверка языка/смены фокуса. Дополнительно запускался существующий `capture_0368_native.py`: обычный прогон не получил закреп по Ctrl+Alt+F7, а диагностический прогон с наблюдением событий прошёл. Этот расширенный тест остаётся нестабильным; результат не засчитывается как успешная полная регрессия горячих клавиш. Его исходник сохранён без изменений, не связанное с двумя исправлениями поведение команд не перерабатывалось.

Компактные подтверждения: [qa-artifacts/shape-type-text-language](qa-artifacts/shape-type-text-language/).
