# Подстановка шаблонов во время ввода

Последующие исправления, новые настройки и форма внутри быстрой палитры:
[qa-quick-palette.md](qa-quick-palette.md). Описание ниже относится к первому этапу.

Реализация: 14 октября 2026. Windows; формат шаблонов и существующая вставка
из палитры сохраняются. Функция выключена по умолчанию.

## Что реализовано

- Режимы по триггеру и постоянно; настраиваемые триггер, вызов, переключение,
  исключения по имени EXE; переключение также доступно в трее.
- Локальный индекс названия и содержимого, приоритет названия, пять результатов.
  Изменения файлов шаблонов и переменных проверяются раз в две секунды.
- Отдельное окно без активации: каретка, поле, центр рабочей области монитора.
  Позиционирование учитывает DPI, границы и отрицательные координаты.
- Перехватчики передают события ограниченной очередью в отдельный MTA-поток.
  Буфер слова ограничен 128 символами; введённый текст не журналируется.
- RU/EN, Shift/Caps Lock, Backspace, последовательная вставка через существующий
  буфер обмена; собственный SendInput маркируется и игнорируется.
- Навигация, мышь, смена цели, сторонний синтетический ввод инвалидируют
  подсказки. После сторонней замены слово восстанавливается только из доступного
  подтверждённого текста поля. Композиция IME блокирует замену.
- Проверка цели перед заменой: Win32 EDIT (позиция и текст), UIA (диапазон),
  ValuePattern (неизменённое значение). Backspace разрешён для непрерывно
  отслеженных ASCII/кириллических фрагментов в ограниченных поддержанных полях.
  После частичного SendInput другая стратегия автоматически не применяется.
- Поля и вложения переходят в существующую палитру. Ошибка сохраняет форму,
  введённые значения и исходное слово. Отмена закрывает сессию замены.

## Автоматические проверки

Выбор выполнен через `npm run test:changed -- --list --focus text-suggestions
--files ...` по файлам этой задачи. Проверки включают пять тестов логики,
три нативных модульных теста, один тест маркировки обычной вставки,
один тест данных, три теста конфликтов клавиш (всего 13 Rust-тестов),
интерфейс подсказок и регрессию настроек горячих клавиш.

Интерфейс: обе темы, переключение режимов, триггер, исключения, отказ сохранения,
отбрасывание старой сессии, выбор мышью, размеры при DPR 1.5, подтверждение,
ошибка/повтор/отмена формы, подтверждение шаблона только с вложением,
обычная вставка из палитры. Регрессия горячих клавиш:
очистка, восстановление, запись, сохранение остальных настроек и геометрия
при ширине 720/950 в обеих темах.

`tests/text_suggestions_native.py` запускает отдельный EXE с feature `inline-qa`,
отдельным идентификатором, SNIPCAST_DATA_DIR и профилем WebView2. Тестовый
SendInput допускается только с отдельной меткой и при наличии изолированного
каталога. В производственной сборке этого режима нет. Реальные физические
события в QA-сборке сбрасывают тестовый контекст и проходят дальше.

## Совместимость и границы проверки

| Приложение / поле | Слово | Плашка | Замена | Подтверждение |
|---|---|---|---|---|
| Win32 EDIT, собственное тестовое окно | Пройдены оба режима, RU/EN, Backspace, поиск по содержимому | Не перехватывает фокус | Простая и подтверждённая форма прошли | Семь групп сценариев в двух изолированных прогонах |
| Win32 password EDIT | Не предлагается | Скрыта | Не выполняется | Пройдена нативная проверка |
| Chrome input | Пройдено | Пройдено | Пройдено без передачи Enter | Итоговый отдельный браузерный прогон |
| Chrome textarea/contenteditable | Пройдено | Пройдено | Пройдено без лишнего перевода строки | Итоговый отдельный браузерный прогон |
| Мессенджер и редактор кода | Не проверено | Не проверено | Не проверено | Нужны отдельные окна и данные |
| Windows Terminal: PowerShell/CMD | Ограниченный непрерывный буфер | Каретка/центр | ASCII/кириллица, без UIA-выделения | Нативная совместимость не подтверждена; первоначально в исключениях |
| WSL и консольные редакторы | Не проверено | Не проверено | Не проверено | Многострочная вставка может исполнять команды; проверять только в изолированной консоли |
| IME | Композиция не заменяется | После доступного подтверждённого текста | Требуется живая проверка | Реальный IME не проверен |
| Повышенное окно | Отключено | Скрыта | Отключена | Проверка уровня целевого процесса |
| Punto/Caramba | Сторонняя инъекция сбрасывает сессию | Устаревшие подсказки скрываются | Только после повторной проверки | Инъекция эмулируется тестом; реальная конвертация не подтверждена |

Неуспешные нативные прогоны не считаются подтверждением совместимости.
Полный тест требует примерно двух минут без пользовательского ввода:
переключение фокуса и физический ввод намеренно отменяют сессию.
Для браузерного прогона предусмотрена предварительная подготовка скрытого
экземпляра Snipcast и фонового Chrome с ожиданием файла-сигнала. Нативный тест
проверяет фокус перед каждой отправкой клавиш, а для клика — принадлежность
окна под указателем. При потере цели ввод прекращается.
Терминалы добавлены в начальные исключения, пока их замена не проверена.
Удаление этих исключений включает исследовательский путь терминальной вставки.
Удерживаемый Enter после подтверждения формы поглощается до отпускания;
проверка этого сценария настоящим SendInput добавлена, итоговый прогон ещё нужен.

Компактные подтверждения находятся в [qa-artifacts/text-suggestions](qa-artifacts/text-suggestions/):
`native-basic.json`, `native-form-and-input.json`, `native-browser.json`,
`scoped-tests.log`, результаты и снимки headless UI. Нативные результаты относятся
к изолированной QA-сборке на этапе проверки; последующая защита удерживаемого
Enter и форма только с вложением проверены модульными/headless проверками,
но повторного нативного прогона этих изменений не было.

## Проверки без вмешательства в рабочий стол

Логика и интерфейс проверяются headless. Нативные перехватчики, UIA, каретка,
фокус и вставка в чужие приложения требуют интерактивного рабочего стола Windows.
Для следующих нативных проверок рекомендована отдельная постоянная Windows VM
с тестовым агентом в вошедшей пользовательской сессии и собственным буфером обмена.
Консоль VM на основном рабочем столе не требуется держать открытой; запуск
агента в неинтерактивной сессии не заменяет такой рабочий стол.

Обычные [Windows-контейнеры](https://learn.microsoft.com/virtualization/windowscontainers/quick-start/lift-shift-to-containers)
не поддерживают необходимый интерактивный GUI. Для разовых проверок возможен
[Windows Sandbox](https://learn.microsoft.com/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file)
с отключённым перенаправлением clipboard и стартовым скриптом; его содержимое
удаляется после закрытия. Постоянная VM удобнее для повторных тестов Chrome,
WebView2 и переключателей раскладки.

На проверенном компьютере Windows 11 Pro компоненты Hyper-V и Sandbox выключены,
VMware/VirtualBox и машины в стандартных каталогах не обнаружены.
Среда виртуализации не устанавливалась и настройки Windows не менялись.
Следующие проверки с захватом фокуса на рабочем столе пользователя не запускаются.

## UIAccess: отдельный этап

UIAccess в этой реализации не включён. По [требованиям Microsoft](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview)
нужны доверенная подпись и защищённое расположение установленной программы.
Перед включением следует подготовить подписанный установщик, манифест
uiAccess, обновление в защищённой папке с проверкой подписи и откатом;
нынешнюю замену EXE обновлятором в собственной папке требуется адаптировать.
После этого отдельно проверять повышенные окна. Не следует запускать всё
приложение с административными правами ради подстановок.

Unicode SendInput остаётся альтернативой для дальнейших проверок отдельных
приложений. Основной путь использует существующую вставку через clipboard;
автоматического переключения стратегии после частичной вставки нет.

## Сборка и очистка

Производственная сборка `npm run tauri build -- --no-bundle` прошла без feature
`inline-qa`; версия разработки остаётся 0.36.11. SHA-256 нового EXE:
`6ffa00c7425782ed5619b18a9463bc0b706de7ef9383cf75ba2002f60311278c`.
Лог сборки сохранён рядом с подтверждениями проверок.

`cargo clean` выполнен только для изолированного каталога этой задачи:
удалено 12 937 файлов, 9.0 GiB промежуточных артефактов. Затем удалены временная
QA-копия приложения, профили Chrome/WebView2, результаты в `.qa-work`,
локальный кэш Vite и 15 каталогов данных модульного теста. Компактные отчёты
и изображения сохранены в `docs/qa-artifacts/text-suggestions`.

После штатного выхода старого экземпляра новый EXE установлен и запущен из
`dist-release/snipcast.exe`. Проверены путь, версия 0.36.11 и совпадение
SHA-256 с подготовленной сборкой; подтверждение — `running-release.json`.
Временный `snipcast-next.exe` и его checksum удалены. В `dist-release/`
остались актуальный EXE и его контрольная сумма.
